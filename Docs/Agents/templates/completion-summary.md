# Completion summary template

Copy this into the final answer of every code task and fill it in.
Sections with no content get the line `- none` — never delete a heading, an empty
*Manual editor steps* section is information too.

```markdown
## Changed
- `<path/to/File.cs>`: <what changed and why>

## Manual editor steps (REQUIRED — the task is not done without these)
- [ ] `<Prefab or scene object>` → wire `_fieldName` to `<object>`
- [ ] `<Assets/Data/...>` → create asset `<Type>` / add row `<...>`
- [ ] `PoolManager` in `SampleScene` → add a `PoolPair` for `<prefab>` (prebaked: `<n>`)

## How to test manually
1. Open `Assets/Scenes/SampleScene/SampleScene.unity`, enter play mode
2. <action> → expected: <result>

## Git handoff
- My changes: `<paths>`
- Already dirty before I started (not mine, untouched): `<paths | none>`
- `.meta` status: `<all present | Foo.cs.meta will be generated by Unity on next editor focus>`
- Suggested commit — **run it yourself after review**:

  git add <explicit paths>
  git commit -m "<Short sentence-case description>"

## Assumptions
- <the reading of the task you chose where it was ambiguous>

## Flagged, not fixed
- <suspicious code, existing rule violation, or unrelated bug you deliberately left alone>
```

## Filling it in

**Changed** — one line per file. "Why", not just "what": `RocketObject.cs: stop the previous
disable routine before starting a new one — pooled rockets reused within 1s kept the old timer`.

**Manual editor steps** — the human must be able to execute the list without reading the code.
Name the exact asset path, the exact component, the exact field. If a new `[SerializeField]` was
added to a ScriptableObject type, list **every existing asset** of that type that now needs a
value.

**How to test manually** — one concrete path through the game, with the observable result. If the
change is invisible at runtime (refactor, guard clause), say so and give the regression check
instead: "select 20 ships and order an attack — behaviour must be unchanged".

**Git handoff** — the agent never stages, commits or pushes
([GIT_RULES.md §0](../GIT_RULES.md)). This block exists so the human can review and commit in one
pass: name your paths, name the paths that were already dirty and are *not* yours (Unity dirties
`Packages/`, `ProjectSettings/` and `*.csproj` by itself), state whether `.meta` twins are in
place, and propose the message in the project's style — English, short sentence-case phrase, no
ticket prefix, no AI attribution.

**Assumptions** — only the ones that would change the work if wrong.

**Flagged, not fixed** — this is where scope discipline gets recorded. Empty is suspicious after
a large task.
